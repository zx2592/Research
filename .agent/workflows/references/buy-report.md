## 裁决标准

| 裁决 | 条件 | 行动 |
| :--- | :--- | :--- |
| 🔴 **熔断驳回** | 组合风险预算闸门未通过（一周内无配置建议 / 出资账户无现金 / 该大类已超配 / preview_trade Denied） | 直接停止，不做任何后续审计 |
| 🔴 **熔断驳回** | 板块 Beta 向下 | 直接停止，不进入后续分析 |
| 🔴 驳回 | 股性恶心 / 内幕消息 / 典型 FOMO / 盈亏比极差 / 隐含 IRR <15% | 止步 |
| 🟡 观望 | 板块势能未确认 / 信号未确认 / 赔率不够 / 现价 > 行动价 / **价格单源未交叉（拿不到可信止损位）** | 补充观察，等回落到行动价或补齐第二个价格来源 |
| 绿色 | 板块势能向上 + 股性流畅 + 逻辑坚实 | 执行买入（进入下方执行闭环） |

## 保存、通知与自动下单执行

1. 先 `check_report_quality(markdown)`；`passed: false` 时按 `missing_sections` / `issues` 补齐后重跑，通过后再用 `write_to_file` 保存报告
2. 在最终回答中向用户展示最终裁决结果 + 交易计划表 + 理性自检问题。
3. **【关键：执行确认】** 
   - 如果你的裁决不是 🔴驳回，你**必须**在最终回答末尾引导用户给出具体下单参数：
   > 💡 **系统提示**: 审计完成且符合风控（已调用 `preview_trade`）。如果你确认执行交易，请直接回复下单指令（例如："市价买入 200 股" 或 "限价 120 买入 100 股，理由是突破支撑位"）。
   
4. **【接收确认 & 系统下单】** 
   - 待用户回复明确的参数（包含价格、数量和定性理由）后，你**必须**静默调用工具 `execute_trade(ticker, side="buy", quantity, order_type, limit_price, rationale)`。
   - `execute_trade` 如果返回成功（包含 commit_hash），在最终回答中告诉用户订单已落账。如果返回错误（如 Pipeline Rejected），告诉用户阻挡原因。

5. 在最终下单成功后附加建议：
   > 💡 **建议**: 建议执行 `/add` 将本次分析的入场逻辑保存到知识库，这将成为未来 `/sell` 追溯「当初为什么买」的最客观依据。
