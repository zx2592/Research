# 深研类阶段三：对抗性复核

> 本文件由 `/deep` 与 `/value` 共用。

报告已落盘。本阶段用**挑错的姿态**重读一遍，只做核对与修补，成本很低——
不加载研究过程，也不加载报告骨架，只带质量门禁。

## 执行

1. `read_file` 读取刚落盘的报告（路径见上一阶段的交接说明，位于 `Reports/deepdive/`）。
2. `check_report_quality(markdown, filename)` 跑一遍，`filename` 必须带上。
3. 按下面的清单逐条对抗性检查——**默认假设有问题，去证伪它**：

| 检查 | 怎么查 |
| :-- | :-- |
| 数字是否有源 | 随机抽 5 个关键数字，逐个回证据台账找对应行；找不到的标 `[UNSOURCED]` 或删除 |
| 结论是否被证据支撑 | 读「结论先行」的评级理由，回台账确认支撑它的证据确实存在且等级足够 |
| 反方是否被稀释 | Bear Case 是否只是走过场？台账里的反方证据是否真的指向风险，而不是「风险已被消化」这类话术 |
| 估值数字是否来自脚本 | 隐含增长率 / 安全边际价必须能对上 `valuation_math.py` 的输出，对不上就是心算，重跑脚本改正 |
| 记分卡是否有依据 | 若报告含质量记分卡，逐维检查「依据」列是否真的支撑该分数，空泛表述按未打分处理 |
| 价格承诺是否有背书 | 给了目标价/止损/盈亏比，就必须有 `cross_validate_price` 的 verdict 行；没有就删掉这些数字 |
| 自检计数是否属实 | 数一遍台账实际行数，与自检里填的数字对账 |
| 与历史是否冲突 | 若与上一份档案结论反转而无 `## 冲突解释`，补上 |

4. 发现问题 → 用 `write_to_file` 修正后重新落盘（同一路径，`mode='w'`）。
5. 没有问题 → 明确回答「复核通过，未发现需要修正的问题」，并列出你实际抽查了哪 5 个数字。

## 本阶段不做的事

- ❌ 不要新增取证（预算多半已耗尽，且本阶段目的是核对而非扩充）
- ❌ 不要为了「显得认真」而改写没有问题的段落
- ❌ 不要新建文件；修正就地覆盖原报告
