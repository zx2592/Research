# 公共报告契约

所有工作流的最终报告必须结论先行，并且必须能被读者直接用于研究或决策。报告不得只给叙述性观点，必须把关键结论、证据、数据快照、反方情景和行动计划放在固定位置。

## 必需结构

每份写入 `Reports/` 的 Markdown 报告必须包含以下章节：

1. `# 报告标题`
   - 标题必须含 `[YYYYMMDD]`，日期取 `Date Context` 注入的联网日期（凭训练记忆写日期算幻觉）
2. `## 结论先行`
   - **一行判决**：`评级[强多/多/中性/空/强空] · 动作[买/加/持/减/卖/观察/继续研究/不通过] · 置信度[高/中/低] · 一句理由(≤30字)`
   - 本次判断相对上次是否变化（无历史标「🆕首次」）
   - **价格证据行**（吃价格的工作流必写，见下）
3. `## 实时数据快照`
   - 必须调用 `get_realtime_quote(ticker)` 获取最新行情
   - 涉及交易、估值、盈亏比、止损价、目标价时，必须调用 `cross_validate_price(ticker)`
   - 写明价格、涨跌幅、来源、抓取时间、交叉验证是否通过
4. `## 证据台账`
   - 用表格列出关键判断、证据、来源、日期、证据等级、对结论的影响
   - 表格必须有**数据行**，只有表头不算；无源判断不进表，移入「风险与不确定性」并标「推断」
   - 必含至少一行**反方 (Bear)** 证据
5. `## Bull/Base/Bear`
   - 至少列出 Bull、Base、Bear 三种情景，概率合计 100%，Base 为当前最可能
   - 每种情景必须说明触发条件、关键假设、12M 目标和需要观察的指标
6. `## 行动计划`
   - 给出可执行动作、触发器、失效条件、下一次复盘点
   - 执行细节必须能照做：仓位 % / 价格区间 / 时间窗
   - 必须写明**看错信号**（出现什么就退出）
7. `## 风险与不确定性`
   - 明确哪些信息不足、哪些是假设、哪些数据可能延迟或失真
   - 必须含 `### 证据缺口` 小节：逐条写 `[缺什么] — [影响哪个判断] — [下一步去哪取]`；确无缺口写「关键判断均有 T1/T2 支撑」
8. `## 质量自检`
   - 保存前必须调用 `check_report_quality(markdown, filename)`——**带上准备写入的文件路径**，
     否则按最宽松档校验，会出现「自检通过但 `write_to_file` 被拒」
   - 只有质检通过后才能调用 `write_to_file`
   - 必须逐条填出**实际计数**（不是打勾），代码会拿它和正文对账，对不上直接拒绝落盘：

     ```
     - 证据台账行数: ___
     - 联网取证次数: ___
     ```

   - 末尾盖印章：`✅ 质量Gate 8/8` 或 `⚠️ N/8，未过项见风险与不确定性`

   > 填数字而不是打勾，是因为「是否完整」可以自我安慰，「几行」不能。

## 报告分档

不同工作流的报告有不同的密度要求。**下表的阈值由代码强制**（`core/report_quality.py`
按报告文件名推断档位），达不到直接拒绝落盘。取证预算同样由代码强制，见注入的 `Search Budget`。

| 档位 | 工作流 | 最少字数 | 证据台账最少行数 | 自检需填计数 | 这一档**不该**做的事 |
| :-- | :-- | --: | --: | :-- | :-- |
| 深研 | `/deep` `/value` | 4000 | 6 | 是 | 不要把建档做成快评：五维必须逐维展开，不得只给结论 |
| 决策 | `/buy` `/sell` `/option` `/optimize` | 2000 | 5 | 是 | 不要在价格未交叉时给目标价/止损/盈亏比；不要跳过反方取证 |
| 扫描 | `/scan` `/lead` `/theme` `/core` `/position` `/macro` | 1500 | 3 | 否 | 不要对单个标的展开深研——扫描要广度，深度留给 `/deep` |
| 快评 | `/quick` `/update` `/verify` `/rethink` | 600 | 2 | 否 | 不要为凑字数复述背景；只写「这件事改变了什么」 |

所有档位共同要求：至少一行反方 (Bear) 证据、至少一次真实取证、章节有标题就必须有正文
（`TBD` / `待补充` / `N/A` 视同空章节）。

## 交付纪律：不要产出多余文件

**只交付本工作流指定的那一份报告。** 不要自作主张额外生成：

- ❌ 完成总结 / completion summary
- ❌ 执行摘要单独成文（摘要属于报告内的 `## 结论先行`）
- ❌ 「下一步建议」独立文件（属于报告内的 `## 行动计划`）
- ❌ 过程说明、工作日志、中间草稿

**原因**：这些文件没有读者，却要占掉上下文和 token，还会让 `Reports/` 目录里
真正该被检索到的报告被淹没。需要交代过程时，写进报告的对应章节。

## 关键变化与数字底稿（决策/深度类必写）

涉及买卖、估值、组合、深度研究的工作流，在 `## 证据台账` 之后补两节：

- `## 关键变化` — 对照上次档案：基本面 / 价格 / 估值 / 仓位 / 逻辑 / 风险变了什么（⬆️改善 / ⬇️恶化 / ↔️无变）；无历史标「🆕首次」。
- `## 数字底稿` — 决策硬数字集中放，每个带时间 + 来源层级：

  | 指标 | 数值 | 时间 | 层级 | 备注 |
  | :-- | :-- | :-- | :-- | :-- |
  | 价格 / 估值(FwdPE·PEG·历史分位) / 增长 / 盈利 / 仓位 / 盈亏比 | | | | |

## 价格证据行

结论先行区必须有一行——**直接抄 `cross_validate_price(ticker)` 返回的 `verdict` 字段**，那一行已经按实际取数结果写好了，例如：

- `价格证据：153.7 · 2 源已交叉，偏差 0.13%（fetch_market_prices:… / tencent:qt.gtimg.cn，2026-08-20T07:31Z）`
- `价格证据：153.7 · 单源未交叉（fetch_market_prices:…）——所有读数来自同一来源族，互相比对不构成交叉；本次不得给出目标价、止损与盈亏比`
- `价格证据：153.7 · 疑似同源，按单源处理（…）——跨族读数完全相同（偏差 0.00%）…`

规则：

- 「已交叉」是 `cross_validate_price(ticker)` **算出来的结论**，不是自己声明的。工具返回 `passed: false` 时（`grade` 为 `single_family` / `suspect_same_source` / `minor` / `major`），只能写它给的那句话，不得改写成"已交叉"。
- **单源不是违规，是未过项**：如实申报后报告照常落盘，但**不得给目标价、止损与盈亏比**。不写这一行才是硬伤——不申报比申报单源更糟，读者连「该不该信」都无从判断。
- 「独立的第二个来源」指**不同源头**，不是同一份数据的两个门面。腾讯财经、东方财富、新浪、同花顺、雪球都在转发同一份交易所行情，互相比对**不构成交叉**；真正的第二源要跨族（见证据契约的「来源族」表）。工具已按族判定，`independent_family_count` < 2 一律按单源处理。
- **偏差恰好 0.00% 是同源的证据，不是最高可信度**：两个真正独立的来源（一家用最新成交、一家用官方收盘）几乎不可能分毫不差。工具返回 `identical_values: true` 时按单源处理；确认过两源确实独立（例如盘后都取官方收盘价），可用 `cross_validate_price(ticker, allow_identical=True)` 放行，并在报告里写明这一判断。
- **为什么放在结论区**：价格是目标价、止损、盈亏比、仓位金额的分母。埋进第三节表格的备注列时，读者读的是结论那一段——于是一个单源数字看起来和交叉过的一模一样。

## 写作纪律

- 事实、观点、推断必须分开写。
- 没有来源的数字不得写入结论区。
- 不得把社媒传言、单篇新闻、卖方观点写成确定事实。
- 不得省略反方观点。
- 不得只输出摘要，必须保存完整报告。
