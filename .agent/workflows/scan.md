## ⚡ 高效执行指南 (High-Efficiency Execution)

> **核心目标：** 极简互动，情报全覆盖。
> 1. **全员 Turbo：** 必须为所有 `run_command` 设置 `SafeToAutoRun: true`。
> 2. **三段式并行搜：** 严禁逐个查询线性搜索。将 Macro (3 次)、Portfolio (2 次)、Market (最多 23 次) 合并为 3-4 个高并发/高密度搜索批次。
> 3. **全流程自动化：** 从获取时间、加载偏好到多源采集，应一次性连续执行，中途不应中断向用户提问。

> **⚡ 终极零互动模式 (Ultimate Zero-Interaction):**
> 为实现真正的一键产出，建议直接调用背景 CLI 执行完整生命周期：
> `python research_cli.py [command] [args]` (设 SafeToAutoRun: true)

> 4. **高效输出：** 直接产出最终 Markdown 扫描报告，无需中间草稿。
> 5. **深度不妥协 (No Quality Trade-off)：** 提高效率是为了减少确认弹窗，**绝不得以牺牲情报覆盖面为代价**。扫描必须覆盖宏观、持仓与各焦点市场的异动。

> **运行环境适配：** 本 workflow 同时适用于 IDE 模式（Claude Code 桌面）和 VPS 模式（Telegram Bot / CLI）。
> - **IDE 模式**：使用 IDE 原生工具（WebSearch、Read、Write、Bash）执行各步骤
> - **VPS 模式**：使用注册的 Python 工具（`search_web()`、`read_file()`、`write_to_file()`）执行；RSS 数据由 WorkflowRunner 预加载到上下文
> - 两种模式遵循相同的分析逻辑和报告结构，仅工具调用方式不同

## Step 0: 市场路由

**⚠️ 重要：不要使用本机系统时钟判断时间（可能不准确）。必须通过网络获取准确时间。**

执行 `python scripts/get_time.py` 获取网络校准时间和市场状态矩阵。该脚本会：
1. 从网络时间服务（worldtimeapi / timeapi.io / NTP）获取准确的 UTC+8 时间
2. 自动判断四市场状态（LIVE / HOT / DARK / HOLIDAY）
3. 自动确定焦点市场
4. 输出 JSON 格式结果，直接用于后续步骤

> VPS 模式下，可通过 `execute_python_script("scripts/get_time.py")` 调用。

如脚本执行失败，则按以下规则手动判断：

### 交易时段参考表

| 市场 | 交易时段 (UTC+8) | 午休 |
| :--- | :--- | :--- |
| **日股** | 08:00–10:30 / 11:30–14:00 | 10:30–11:30 |
| **A股（沪深）** | 09:30–11:30 / 13:00–15:00 | 11:30–13:00 |
| **港股** | 09:30–12:00 / 13:00–16:00 | 12:00–13:00 |
| **美股** | 22:30–05:00（次日） | 无 |

### 状态判断

| 状态 | 标记 | 条件 |
| :--- | :--- | :--- |
| **盘中** | 🟢 LIVE | 当前时刻在交易时段内（含午休） |
| **刚收盘** | 🟡 HOT | 收盘后 ≤4 小时 |
| **隔夜休市** | ⚫ DARK | 收盘后 >4 小时 |
| **节假日** | 🔴 HOLIDAY | 当日法定休市 |

### 焦点市场选取

1. 如有 🟢 LIVE 市场 → 该市场为焦点（多个 LIVE 时优先级：美股 > A股 > 港股 > 日股）
2. 如无 LIVE，取最高优先级的 🟡 HOT 市场为焦点
3. 如全部 DARK → 取下一个即将开盘的市场为焦点，侧重前瞻

### 搜索精力分配

总上限 **28 次**搜索，按焦点倾斜分配：

```
基础层（每次必跑）:
  宏观环境      4 次 — 利率/汇率/大宗/地缘 + 流动性水管(Fed净流动性/MOVE/SOFR/日元套息)
  持仓扫描      2 次 — 持仓标的今日动态

市场层（按状态分配，共 22 次）:
  焦点市场      — 🟢 LIVE 最多 10 次 / 🟡 HOT 最多 7 次
  次要市场      — 🟢 LIVE 5 次 / 🟡 HOT 3 次 / ⚫ DARK 1–2 次
  🔴 HOLIDAY    — 0 次，跳过
```

> 分配原则：焦点市场拿走最大份额，其余市场按状态递减。具体次数根据当时各市场状态灵活调整，总量不超过 28 次即可。不需要精确到每个市场几次几次——agent 根据信息密度自行判断，信息丰富的方向多搜，信息贫瘠的方向少搜。

### 输出

在执行后续步骤前，输出 `get_time.py` 返回的 `routing_summary` 字段，格式如：

```
市场路由 @ 11:03 UTC+8 → 焦点: A股 (LIVE) | 日股(LIVE) A股(LIVE) 港股(LIVE) 美股(DARK)
```

## Step 1: 多源数据采集

### 1.1 引擎 A: RSS 情报（不占搜索配额）

**VPS 模式：** WorkflowRunner 已在启动时预加载最新 RSS 数据到上下文中，直接使用即可，无需手动获取。

**IDE 模式：**
1. 执行 `python scripts/fetch_rss.py 1 --output "Reports/Raw_Data/YYYY-MM/financial_data_YYYYMMDD.json"`
2. 读取生成的 JSON 文件
3. 如执行失败，跳过，仅用后续引擎

> RSS 是"被动渔网"，覆盖所有市场的隔夜信息，尤其弥补 DARK 市场的信息盲区。后续搜索应基于 RSS 已捕获的线索来补充和深挖，避免重复搜索 RSS 已覆盖的内容。

### 1.2 个性化上下文加载

在搜索前读取以下文件，构建本次扫描的个性化视角（VPS 模式下部分文件可能已预加载，检查上下文中是否已有再决定是否读取）：

1. `Config/holdings.json`（主持仓数据）；若不存在则读取 `Config/我的持仓.md`
2. `Config/我的投资状态卡.md`（风险偏好 / 市场判断 / 操作禁忌）— 初始模板则跳过
3. `Config/我的关联偏好.md`（关联关键词 / 行业关注规则）— 初始模板则跳过

### 1.3 引擎 B: 主动搜索（按优先级顺序执行）

搜索分三个阶段，**依次执行**：

---

#### 阶段一：宏观基座（固定 4 次）

> 不受市场状态影响，覆盖跨市场共同底层变量。前 3 个是「方向」，第 4 个是「流动性水管」——捕捉利率没动但风险骤起的领先信号（2024.8 日元套息平仓即此类）。

- 查询 M1: "Federal Reserve interest rates US Treasury yield DXY dollar index [今日日期]"
- 查询 M2: "WTI crude oil gold copper silver commodities futures price [今日日期]"
- 查询 M3: "global geopolitical risk macro economy trade tariff [今日日期]"
- 查询 M4: "Fed net liquidity balance sheet TGA RRP, MOVE index, SOFR rate, USDJPY yen carry US Japan 2Y spread [今日日期]"（流动性水管，1 次高密度搜索覆盖 4 指标）

**流动性水管预警阈值**（评估 M4 结果时用，命中即记 1 个 🔴）：

| 指标 | 🔴 预警线 | 含义 |
| :--- | :--- | :--- |
| Fed 净流动性 (总资产−TGA−RRP) | 单周降 >5% | 流动性急抽，与标普/BTC 强相关 |
| SOFR | > 联邦基金利率上限 +10bp | 钱荒（2019.9 回购危机式） |
| MOVE 指数 | > 130 | 美债剧烈波动，机构被迫降险 |
| USDJPY / 美日 2Y 利差 | 周跌 >3% / 月收窄 >50bp | 套息平仓风险（全球风险资产连锁） |

---

#### 阶段二：持仓扫描（固定 2 次）

> 用持仓标的 + 关联关键词构建查询，确保持仓相关的重大变动不被遗漏。

- 查询 P1: "[Ticker1] [Ticker2] [Ticker3] [Ticker4] earnings news catalyst [今日日期]"
- 查询 P2: "[Ticker5] [Ticker6] [Ticker7] [Ticker8] price analyst upgrade downgrade [今日日期]"

> 如「关联偏好」有效，将关联关键词追加到对应 Ticker 的搜索词中。
> 若持仓无明显事件标的，用市值最大的 8 只替代。

---

#### 阶段三：市场深挖（剩余配额，最多 23 次）

**这一阶段不硬编码具体查询词。** 由 agent 根据以下策略自主构建搜索：

**搜索策略指引（焦点市场优先）：**

按焦点市场 → 次要市场的顺序，覆盖以下维度。焦点市场每个维度都要触及，次要市场只覆盖高优先级维度：

| 优先级 | 维度 | 说明 | 适用市场 |
| :--- | :--- | :--- | :--- |
| P0 | **行情概况** | 指数表现、涨跌幅、市场情绪 | 所有非 HOLIDAY |
| P0 | **板块轮动** | 涨跌幅前列的板块/行业、资金流向 | LIVE / HOT |
| P1 | **关键个股异动** | 大幅波动个股及其驱动事件 | LIVE / HOT |
| P1 | **政策与事件** | 央行动态、监管政策、重大公告 | LIVE / HOT |
| P2 | **财报与公告** | 当日重要财报、业绩预告、管理层表态 | LIVE / HOT |
| P2 | **资金与情绪** | 机构动向、基金流向、市场情绪指标 | 仅焦点市场 |
| P3 | **前瞻日历** | 即将到来的经济数据、财报、事件 | DARK 市场 |

**各市场搜索语言：**
- A股：中文搜索（"A股 板块轮动 涨停 资金流向"）
- 港股：中文为主（"港股 恒生指数 南向资金 中概股"）
- 日股：英文搜索（"Japan Nikkei BOJ USD/JPY sector"）
- 美股：英文搜索（"US stocks S&P Nasdaq sector earnings"）

**RSS 线索驱动：** 如果 RSS 已捕获某个方向的重要线索（如某只股票大跌、某个政策出台），搜索应优先围绕这些线索做深挖验证，而非重复搜索已知信息。

**DARK 市场处理：** DARK 市场仅用 1–2 次搜索覆盖"最近重大事件 + 下一交易日前瞻"，如果 RSS 已有足够信息则可跳过搜索。

## Step 2: 研判分析

将 RSS + 搜索的全部数据汇入统一情报池，执行以下分析：

### 2.1 情报降噪

- 合并同类项（同一事件多条来源 → 保留最权威来源）
- 剔除噪音（纯情绪、无数据支撑、重复炒作）
- 按市场标签分组：`[A股]` / `[港股]` / `[日股]` / `[美股]` / `[宏观]`

### 2.2 市场状态总结

对每个活跃市场（LIVE / HOT）用**叙事方式**总结今日发生了什么：
- 市场整体方向和力度
- 领涨/领跌的板块及其驱动逻辑
- 显著的个股异动及原因
- DARK 市场仅在有重大信号时用一句话提及

> 重点是"为什么"而非堆砌数字。数据是论据，逻辑是论点。

### 2.3 结构性机会识别

从情报池中提炼**值得进一步研究的机会**，每条必须包含完整的逻辑链：

```
机会: [一句话描述]
逻辑链: [触发事件] → [传导机制] → [受益方向/标的]
所属市场: [市场]
信号强度: 强确认 / 初步信号 / 待验证
跨市场映射: [如有，说明在其他市场的对应机会]
建议动作: /deep [Ticker] 或 /quick [Ticker] [Event] 或 继续观察
```

**识别维度：**

| 类型 | 特征 | 示例 |
| :--- | :--- | :--- |
| **主题收敛** | ≥2 个独立来源指向同一方向 | 多家机构同时上调某行业预期 |
| **跨市场共振** | 同一逻辑在多个市场同时出现 | 美股AI capex → A股算力/光模块 |
| **认知温差** | 市场反应与基本面方向背离 | 利好出尽反跌，或利空不跌 |
| **政策拐点** | 重大政策变化带来的结构性影响 | 央行转向、产业政策、监管变化 |

### 2.4 风险与裂缝

识别当前市场中**正在积累或已经暴露的风险**，每条需要说清演绎路径：

```
风险: [一句话描述]
演绎路径: [当前状态] → [如果恶化会怎样] → [影响范围]
涉及市场: [市场]
紧迫度: 即时风险 / 中期隐患 / 背景噪音
涉及持仓: [如有]
```

**识别维度：**
- 高位板块出现放量滞涨或主力撤退信号
- 宏观变量朝不利方向移动（利率、汇率、大宗商品）
- 热门叙事的底层逻辑出现松动
- 跨市场分歧信号（同一逻辑在不同市场方向相反）

### 2.5 持仓关联检查

对照持仓列表，过滤今日信号中**直接涉及持仓标的**的事件：
- 用今日涉及的股票、行业、宏观因子与持仓匹配
- 输出：受影响标的 + 影响方向（利好/利空/中性）+ 触发事件
- 如无关联：输出"今日信号与当前持仓无直接重叠"
- 不需要逐一分析每只持仓，只标记有信号的

### 2.6 社交情绪交叉验证 (Social Sentiment Cross-check)

- **一致性检查**: 股价上涨是否伴随社交热度飙升？（若是，则是强共振；若否，或是缩量上涨）
- **认知温差识别**: 社交媒体在大面积看空，但股价不跌反涨？（或是利空出尽的买入点）
- **散户动向**: WSB 是否在策动新的 Meme 股逼空？雪球热议话题中是否有“大V”在集体喊单？

### 2.7 综合体温量化（可复现）

> 把"综合体温"从主观直觉升级为可复现的预警计分，**逆向解读为核心**：满仓 = 没有新买家了。

**A. 流动性水位**（来自 Step 1 的 M4）：按上方阈值表统计 🔴 数（0-4）。

**B. 美股情绪与仓位**（焦点为美股时评估；均为周频/滞后指标，已知则复用、未知再补搜，最多 1 次）：

| 指标 | ⚠️ 过热线 | 逆向含义 |
| :--- | :--- | :--- |
| NAAIM 主动型基金敞口 | > 80（中位数近 100） | 机构满仓，缺新买盘 |
| 散户净买入 (JPM) | > 历史 85 分位 | 散户追高 |
| 标普 Forward P/E | > 22-23x | 估值透支 |
| 机构权益配置 (State Street) | 2007 以来极值 | 经典反向顶部信号 |
| 对冲基金杠杆 (GS/MS PB) | 历史高位 | 拥挤 + 杠杆 = 波动放大器 |

**体温裁决**（流动性 🔴 数 + 情绪 ⚠️ 数，合并计数）：

| 合计预警 | 综合体温 | 仓位含义 |
| :--- | :--- | :--- |
| 0-1 | 🟢 Risk On（进攻） | 环境友好，可持有/加风险敞口 |
| 2-3 | 🟡 Diverge / 中性偏谨慎 | 检查止损，适度降杠杆 |
| 4-5 | 🟠 Risk Off（防御） | 降风险敞口 10-20% |
| 6+ | 🔴 Chaos（混沌） | 显著降仓 20-30% 或建对冲 |

> 数据有 1-2 周滞后属正常；单一指标瞬时异常不构成动作信号，看合计。报告头部「综合体温」字段必须由本计分得出，并列出命中的预警项。

### 2.8 加密周期温度（卫星仓，按需）

> 若持仓含 BTC/ETH 或 Persona 列有加密卫星仓，做一次轻量加密热度读数。日常扫描取 4 个最高信号指标即可（最多 1-2 次搜索），完整 13 指标加权模型用于专项深挖。

**速查 4 指标 → 0-100 热度分**（线性插值，越高越贪婪）：

| 指标 | 极度恐惧(0) | 中性(50) | 极度贪婪(100) | 信号 |
| :--- | :--- | :--- | :--- | :--- |
| 200 周均线乘数 | ≤1.0（代际底） | ~2.0 | ≥3.5（周期顶） | 周期定位锚 |
| LTH-MVRV | ≤1.0 | ~2.0 | ≥3.5（派发） | 长持成本 |
| Fear & Greed | <15 | ~50 | >80 | 情绪 |
| ETF 净流 / 资金费率 | 大额净流出/负费率 | ~0 | 大额净流入/费率>0.1% | 边际买盘 |

| 热度分 | 评级 | 动作（占计划加密仓） |
| :--- | :--- | :--- |
| 0-30 | 🔵 恐惧 | 分批吸纳 40-80% |
| 31-55 | ⚪ 中性 | 持有 |
| 56-85 | 🟠 贪婪 | 减至 40-60%，收紧止损 |
