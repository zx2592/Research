// turbo-all

> **契约**：本工作流的报告必须遵守注入在本文件之前的三份公共契约（报告结构 / 证据标准 / 质量门禁）。本工作流的核心就是「和上次比什么变了」——**`## 关键变化` 是它的心脏**，缺这一节等于没做 update。财务与估值数字守证据契约：≥2 个独立来源交叉、每个数字带时间。

> **定位区分：**
> - `/update [Ticker]` — 时间驱动，"最近怎么样了"，回顾 2-4 周动态，中等深度
> - `/quick [Ticker] [Event]` — 事件驱动，"刚发生了这件事"，聚焦单一事件，快速定性
> - `/deep [Ticker]` — 首次建档或年度重审，全面深度分析
>
> **运行环境适配：** 同时适用于 IDE 模式和 VPS 模式，工具调用方式参见 scan.md 说明。
>
> ## ⚡ 高效执行指南 (High-Efficiency Execution)
>
> > **核心目标：** 极简互动，一令即达。
> > 1. **全员 Turbo：** 必须为所有 `run_command` 设置 `SafeToAutoRun: true`。
> > 2. **聚合搜索：** 严禁单维度重复搜索。将「新闻、财报、分析师预期、股价技术面」合并为 1 次高密度聚合搜索。
> > 3. **全流程自动化：** 除非涉及买卖金钱决策，否则中途无需询问，直接产出最终报告。
> > 4. **深度不妥协 (No Quality Trade-off)：** 提高效率是为了减少确认弹窗，**绝不得以牺牲分析深度为代价**。报告必须严格遵循各 Phase 的维度要求，确保逻辑链条完整、数据交叉验证充分。

> **⚡ 终极零互动模式 (Ultimate Zero-Interaction):**
> 为实现真正的一键产出，建议直接调用背景 CLI 执行完整生命周期：
> `python research_cli.py [command] [args]` (设 SafeToAutoRun: true)


## 解析参数

- `/update [Ticker]`（如 `/update GOOG`）
- 自然语言触发："GOOG 最近怎么样了"、"帮我看看 SPOT 有什么变化"

## Step 0: 知识库预检

> **目的：** update 的核心价值是"和上次对比有什么变化"。必须先找到基准，才能识别增量。

**查询步骤**（按顺序，命中即停）：

**① 查 KB 索引**
- 读取 `Memory_Layer/Knowledge_Base/KB_INDEX.md`
- 搜索 `[Ticker]` / `[公司中文名]`
- **命中** → 读取知识卡片 + 关联报告（deepdive / quick / update）→ 提取「上次核心逻辑 + 上次估值锚点 + 已识别风险」作为基准

**② 扫描历史报告**
- 扫描 `Reports/` 和 `Reports/deepdive/`，查找包含 `[Ticker]` 的文件（最近 90 天）
- **命中** → 读取最新一份报告的结论段落作为基准

**③ 查持仓状态**
- 读取 `Config/holdings.json`，确认是否为持仓标的
- 如是持仓 → 提取持仓数量、成本线、策略分类（Long-Term Core / Short-Term Satellite）
- 读取 `Config/我的投资状态卡.md`，检查是否涉及当前操作策略

**基准输出**（内部使用，不写入报告正文）：
```
基准状态:
- 上次研究: [日期] [来源文件]
- 核心逻辑: [一句话]
- 估值锚点: [PE/目标价/关键支撑位]
- 持仓状态: [持仓/未持仓] [成本线] [策略]
- 已识别风险: [列出]
```

如全部未命中 → 标注「🆕 首次关注」，后续步骤按全量模式执行。

## Step 1: 多维情报采集（聚合模式）

> **搜索策略：** 仅限 1-2 次搜索，覆盖全维度。

- **聚合查询：** `[Ticker] [Company] latest news earnings analyst rating price target stock technical analysis [当前月份] [当前年份]`
- **当日复用：** 今天已跑过 `/scan` 或 `/core` 的，其宏观读数与板块景气直接引用（带原时间戳，不是"旧数据"），把搜索预算留给个股增量。
- **取证走本项目工具：** `search_web` / `browser_fetch` / `drill_source`；行情用 `get_realtime_quote`，涉及目标价、止损、盈亏比时必须 `cross_validate_price`。

**采集要点：**
- 财报/业绩预告及管理层指引
- 分析师评级/目标价变动 (Upgrade/Downgrade)
- 关键技术位（支撑/阻力/均线）与趋势判断
- 行业竞争格局及地缘影响 (如适用)

## Step 2: 边际变化分析

> **核心任务：和基准对比，识别"什么变了"。**

### 2.1 事件时间线

将采集到的所有事件按时间排列，形成近 2-4 周的事件脉络：

```
[日期] [事件1] — [影响定性]
[日期] [事件2] — [影响定性]
...
```

### 2.2 边际变化提炼

从事件时间线中提炼**真正重要的边际变化**（不是所有新闻都重要）：

| 维度 | 上次基准 | 当前状态 | 变化方向 |
| :--- | :--- | :--- | :--- |
| 核心逻辑 | [上次的判断] | [是否有变化] | 增强/削弱/不变 |
| 财务表现 | [上次数据] | [最新数据] | 好转/恶化/持平 |
| 估值水平 | [上次锚点] | [当前估值] | 便宜了/贵了/合理 |
| 分析师共识 | [上次评级] | [当前评级] | 上调/下调/维持 |
| 行业地位 | [上次判断] | [是否有变化] | 加强/削弱/不变 |

### 2.3 逻辑校验

将边际变化对照投资逻辑进行校验：

- **逻辑增强：** 哪些新信息支持了原有逻辑？
- **逻辑削弱：** 哪些新信息动摇了原有逻辑？需要重估吗？
- **新增变量：** 是否出现了之前未考虑的因素？
- **风险更新：** 已识别风险是否兑现/消除/加剧？有新风险吗？

### 3.1 估值快照

> 每个数字必须带**来源 + 时间 + 层级**；财务与估值数字尽量两个独立来源交叉，不一致时并列写出并说明取舍。取不到的写「未取到」，记入证据缺口，**不得用训练记忆里的数值补洞**。

| :--- | :--- | :--- |

| PE (TTM) | | vs 5 年中位数 |
| PE (Forward) | | vs 行业平均 |
| 市值 | | |
| 分析师目标价中位数 | | vs 当前价（上行/下行空间）|

### 3.2 持仓审视（仅持仓标的）

- **盈亏状态：** 当前价 vs 成本线，浮盈/浮亏幅度
- **仓位合理性：** 当前仓位占比是否与信心水平匹配
- **策略一致性：** 是否与状态卡的操作方向一致
- **需要行动吗？** 加仓 / 减仓 / 止损 / 持有 / 需要 `/deep` 重估

## Step 5: 保存与通知

### 保存报告
1. 先 `check_report_quality(markdown)`；`passed: false` 时按 `missing_sections` / `issues` 补齐后重跑。
2. 通过后 `write_to_file` 保存到 `Reports/YYYYMMDD/YYYYMMDD_[Ticker]_Update.md`（路径相对项目根目录）。

### 知识库更新提示
> 若本次刷新揭示了重要的边际变化（逻辑增强/削弱、估值锚点大幅移动、新风险出现），建议执行 `/add` 将变化追加到知识库卡片，保持档案时效性。
