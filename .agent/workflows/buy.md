## Step 1: 前置熔断检查

> ⚠️ 以下两条**任一不满足**，直接 🔴 驳回，不进入后续分析：

### 1.1 板块 Beta 必须向上
- 板块指数/ETF 是否处于周线右侧（MA20 以上）？
- **铁律：板块 Beta 向下时直接驳回。在泥沙俱下的 Beta 面前，个股 Alpha 一文不值。**

### 1.2 行业性质确认
- 所属行业是增量市场还是存量厮杀？
- 存量厮杀板块（如价格战中的行业）只能短打，不能长持

**搜索动作**: 板块指数/ETF 走势、行业竞争格局

## Step 2: 个股股性审查

- [ ] 走势是否流畅？（非磨叽、非频繁假突破）
- [ ] 是否避免长上下影线「偏炮」？
- [ ] 成交量是否健康配合？（放量涨、缩量跌）
- [ ] 是否有明确的支撑/阻力位可供设置止损？

**铁律：股性恶心的票不玩。走势磨叽 = 摩擦成本高 = 利润被消耗。**

---

## Step 3: 策略定位

### 长线护城河
- 是在寻找"回调的黄金坑"还是"右侧的确认点"？
- 当前价格相比内在价值是否处于合理/低估区间？

### 短线势能
- 是在寻找"突破的爆发点"？
- 是否处于"板块确认起势 + 龙头短暂回调"的 moment？

---

## Step 3.5: Action Price 推导（反锚定纪律）

> **铁律：先独立估值，最后才看现价。** 杜绝"先看现价 → 反推一个看起来合理的目标价"的锚定陷阱。执行顺序严格如下：

1. **独立估值**：用 ≥2 种方法给出内在价值 / 合理区间（**此步不看现价**）
2. **扣安全边际**：合理价 × (1 − 安全边际%) → **Action Price（行动价）**
3. **再看现价**：现价 ≤ Action Price 才进入买入区；现价 > Action Price → 🟡 等待回落
4. **IRR 地板**：以现价买入、目标价兑现的年化回报 (IRR) 必须 **≥ 15%**（长线）。低于地板，即使盈亏比达标也驳回——**赔率好 ≠ 期望回报够**。

---

## Step 4: 交易计划审计

1. **Stop Loss（防守位）**
   - 跌破哪个价格说明逻辑失效或势能结束？
   - 止损价: [具体数字]（对应亏损: -X%）
2. **Take Profit（目标位）**
   - 潜在上涨空间在哪里？（前高？估值修复？）
   - 目标价: [具体数字]（对应盈利: +Y%）
3. **R/R Ratio（盈亏比）**
   - 盈利幅度 / 亏损幅度 = [数值]（参考标准 > 1:3）
4. **隐含 IRR（期望回报地板）**
   - 现价 → 目标价的年化回报 = [数值]%（长线地板 ≥15%；短线视持有期）
   - 与盈亏比是**双重门槛**：两者任一不达标都不算合格买点

---

## Step 5: 纪律合规审查

逐条扫描以下禁忌：

### 🟥 红线禁忌（触发则直接驳回）
- 是否使用杠杆/配资？
- 是否在牛市中做空？
- 买入理由中是否带有"报复市场"、"急于回本"、"必须现在买"的情绪词？

### 🟨 信息洁癖
- 是否在用 Class B 信息（情绪/传闻/大V观点）驱动长线持仓决策？

---

## Step 6: 理性自检

引导用户思考 4 个问题：
1. 我现在想买，是基于系统逻辑信号，还是怕踏空的焦虑 (FOMO)？
2. 走势流畅度是否符合要求？介入后是否会产生不必要的摩擦？
3. 如果买入后下一秒跌 10%，我的应对预案是什么？
4. 如果未来半年它都不涨甚至阴跌，我拿得住吗？仓位有没有超限？

## 裁决标准

| 裁决 | 条件 | 行动 |
| :--- | :--- | :--- |
| 🔴 **熔断驳回** | 板块 Beta 向下 | 直接停止，不进入后续分析 |
| 🔴 驳回 | 股性恶心 / 典型 FOMO / 盈亏比极差 / 隐含 IRR <15% | 止步 |
| 🟡 观望 | 板块势能未确认 / 信号未确认 / 赔率不够 / 现价 > 行动价 | 补充观察，等回落到行动价 |
| 绿色 | 板块势能向上 + 股性流畅 + 逻辑坚实 | 执行买入（进入下方执行闭环） |

## 保存、通知与自动下单执行

1. 用 `write_to_file` 保存报告
2. 在最终回答中向用户展示最终裁决结果 + 交易计划表 + 理性自检问题。
3. **【关键：执行确认】** 
   - 如果你的裁决不是 🔴驳回，你**必须**在最终回答末尾引导用户给出具体下单参数：
   > 💡 **系统提示**: 审计完成且符合风控（已调用 `preview_trade`）。如果你确认执行交易，请直接回复下单指令（例如："市价买入 200 股" 或 "限价 120 买入 100 股，理由是突破支撑位"）。
   
4. **【接收确认 & 系统下单】** 
   - 待用户回复明确的参数（包含价格、数量和定性理由）后，你**必须**静默调用工具 `execute_trade(ticker, side="buy", quantity, order_type, limit_price, rationale)`。
   - `execute_trade` 如果返回成功（包含 commit_hash），在最终回答中告诉用户订单已落账。如果返回错误（如 Pipeline Rejected），告诉用户阻挡原因。

5. 在最终下单成功后附加建议：
   > 💡 **建议**: 建议执行 `/add` 将本次分析的入场逻辑保存到知识库，这将成为未来 `/sell` 追溯「当初为什么买」的最客观依据。
