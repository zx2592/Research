AI Investment Research System - 系统操作手册

本文档详细说明了系统的架构设计、核心功能及操作指南。

1. 系统架构 (System Architecture)

本系统采用 "Eyes - Brain - Memory" 三层仿生架构，旨在模拟人类研究员的信息处理流程。

第一层：Eyes (感知层 - 信息获取)

负责从外部世界获取原始数据。

  • 主动视觉 (Active):
    • 搜索: 集成搜索引擎 API，用于实时事件验证和深度话题挖掘。
    • 数据: 通过行情接口拉取全球市场实时价格与基本面数据。
  • 被动视觉 (Passive):
    • 信息监控: 定时从设定好的信息源（含 RSS 订阅源）抓取新闻与研报，存入本地缓存作为系统的"每日早餐"。

第二层：Brain (认知层 - LLM 处理)

系统的核心处理单元。

  • 双核引擎:
    • Desktop Mode: 在 IDE 中直接调用本地配置的 Agent，适合交互式深度研究。
    • Server Mode: 在后台服务中运行，调用大模型 API，适合自动化任务（如每日晨报扫描）。
  • 技能库 (Skills):
    • Standard SOPs: 结构化的标准作业程序，如市场扫描、深度研究。
    • Cognitive Models: 基于自然语言的模糊指令集，如 "跑一下市场洞察"。

第三层：Memory (记忆层 - 知识归档)

负责研究成果的沉淀与复用。

  • Research Reports: 存放生成的研报，按日期和类型结构化归档。
  • Raw Data Cache: 短期记忆，存储最近的原始资讯。
  • Knowledge Base: 长期记忆，将核心洞察转化为永久知识卡片。

2. 核心功能与操作 (Functions & Operations)

您可以通过 CLI 命令行 或 IDE 对话 两种方式驱动系统。

A. 市场扫描 (Market Scan)

功能: 每天早晨从海量资讯中提炼高价值信号，去除噪音，识别"主题收敛"与"高影响异常"。

  • 触发:
    • CLI: python [cli_tool] scan
    • IDE: "跑一下市场洞察" 或 /scan
  • 输入: Data Collector 抓取的数据。
  • 输出: 包含战略仪表盘、势能详解、风险预警的日报。

B. 深度研究 (Deep Dive)

功能: 对特定公司或话题进行 360 度无死角研究。

  • 触发:
    • CLI: python [cli_tool] deep [NVDA]
    • IDE: /deep NVDA 或 "调研一下 NVDA"
  • 流程:
    1. 搜集最新的 10k/10q 财务数据。
    2. 搜索最近的电话会 (Earnings Call) 纪要。
    3. 分析竞争对手与行业趋势。
    4. 输出包含 bull/bear case 的深度投研报告。

C. 快速评论 (Quick Take)

功能: 针对刚刚发生的突发事件（如财报发布、突发新闻）生成快速点评。

  • 触发: python [cli_tool] quick TSLA "Robotaxi 发布会"
  • 输出: 短小精悍的点评，适合发推或社群分享。

D. 价值分析 (Value Check)

功能: 基于"质量复利"模型，检查公司的护城河、ROCE 和估值安全边际。

  • 触发: /value MCO (穆迪)
  • 输出: 包含反向 DCF 估值、护城河评级的体检报告，判断是否值得买入。

E. 事实核查 (Verify)

功能: 验证传闻的真实性。

  • 触发: /verify "iPhone 18 将采用钛合金外壳"
  • 输出: 引用多方信源的真伪判断报告。

3. 维护与配置 (Maintenance)

信息源管理

  • 配置文件: 数据采集服务的配置文件。
  • 修改方法:
    1. 打开配置文件，找到源列表。
    2. 取消注释或添加新的 RSS URL。
    3. 注意: 如果是 RSSHub 源，请使用配置好的 Base URL 变量。
    4. 测试: 运行采集脚本并指定小范围时间窗口验证。

报告归档

系统会自动将报告按月分类。建议定期（每季度）将 Reports/ 目录下的内容备份或同步到 Obsidian/Notion 以建立永久知识库。

模型切换

  • 配置文件: 环境变量配置文件 (.env)
  • 参数: LLM_MODE
    • auto: 自动选择。
    • desktop: 强制使用 IDE 内置模型。
    • vps: 强制使用 API Key 调用。

4. 常见问题 (Troubleshooting)

  • Q: 抓不到数据？
    • A: 检查采集参数。如果源更新频率低（如周更），请扩大抓取时间范围（如 5 天）。
  • Q: 控制台输出乱码？
    • A: 某些环境下直接重定向输出可能存在编码问题。建议直接查看控制台打印，或检查日志文件。
  • Q: 503 错误？
    • A: 这是目标源的反爬虫或服务不稳定。系统会自动跳过该源继续执行。可稍后重试或寻找替代源。
