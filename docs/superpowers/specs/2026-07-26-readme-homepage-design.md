# Research 项目首页改写设计

## 目标

将 `README.md` 改写为可直接提交的现代化开源项目首页。首页同时服务两类读者：

- 希望快速理解并运行系统的投资研究用户；
- 希望评估架构、扩展能力并参与贡献的开发者。

改写以仓库当前实现为唯一事实来源，不虚构截图、许可证、性能指标、稳定性承诺或尚未实现的功能。

## 内容策略

采用“上手优先、逐层深入”的双层结构：

1. 首屏用简洁标题、定位语、能力摘要和状态提示回答“它是什么、解决什么问题、现在能做什么”。
2. 通过核心能力与工作流概览帮助读者快速判断是否适用。
3. 提供从仓库根目录执行的最短可行安装、配置和 CLI 示例。
4. 在后半部分展开 Eyes–Brain–Memory 架构、模块边界、数据流、Provider、数据源、自动化服务和安全设计。
5. 用项目结构、测试、路线图和贡献指南服务开发者。

## 技术事实边界

README 中的命令、路径、环境变量和能力声明必须分别与以下实现核对：

- CLI 与命令参数：`research_cli.py`
- Python 依赖：`requirements.txt`
- Node 依赖：`package.json`
- 配置项：`config.yaml.example`、`core/settings.py`、`core/config.py`
- LLM Provider 与模型路由：`core/llm_providers.py`、`core/llm_client.py`
- 数据源：`services/datahub/sources/`
- 执行、组合与触发子系统：`services/execution/`、`services/portfolio/`、`services/trigger/`
- 工作流定义：`.agent/workflows/`
- 测试方式：`pytest.ini`、`tests/`
- 当前与后续范围：`CHANGELOG.md`、`Development_Roadmap_Summary.md`、`next phase.md`

若文档与实现冲突，以当前默认分支代码为准；无法从仓库验证的内容不写成既成事实。

## 表达与视觉

- 主体使用简体中文，保留必要的英文技术名词。
- 控制徽章数量，只使用能从仓库事实支持且不会误导的静态信息。
- 使用一个紧凑的文本架构图，不依赖外部图片资源。
- 表格仅用于功能映射、Provider 配置和工作流速查。
- 将长篇方法论移交给现有详细文档，首页提供摘要与链接。
- 安装命令统一假定读者位于仓库根目录，避免现有 README 中 `research/` 路径歧义。

## 项目状态与风险沟通

首页应明确该项目是面向研究与自动化实验的开源系统，不构成投资建议。涉及交易执行的能力应描述为带保护链和适配器的可选子系统，不暗示默认启用或保证资金安全。涉及个人持仓、密钥、报告和本地配置时，应说明示例文件与忽略规则，并提醒用户自行检查提交内容。

## 验收标准

- 首屏能在一分钟内说明项目用途、适用对象和核心差异。
- 新用户可以仅凭快速开始完成依赖安装、配置准备、CLI 帮助查看和首个命令调用。
- 架构、功能、Provider、数据源和路径均能在仓库中找到对应实现。
- README 包含目的、架构、功能、安装、使用、路线图和贡献指南。
- 所有仓库内链接可解析，Markdown 标题与目录锚点一致。
- 不出现占位符、失效的 `.env.example` 引用或未经验证的承诺。
